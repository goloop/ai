# ai - довідник

Повний довідник пакета `ai`: провайдер-незалежний інтерфейс `Client`, спільна
модель запиту й відповіді, якою «говорить» кожен драйвер, і транспортний
плюмбінг, який перевикористовують автори драйверів.

## Ментальна модель

Пакет `ai` повторює прийнятий у стандартній бібліотеці поділ на інтерфейс і
драйвери - так само, як `database/sql` відокремлений від своїх драйверів, а
`log/slog` від своїх handler-ів. Цей пакет тримає спільний контракт; окремий
пакет на кожного провайдера (`anthropic`, `openai`, `gemini` тощо) його реалізує.
Драйвер залежить лише від `ai`, тож увесь набір лишається без сторонніх
залежностей.

Код проти інтерфейсу працює з будь-яким провайдером - міняється лише
конструктор, виклики ті самі:

```go
import (
	"github.com/goloop/ai"
	"github.com/goloop/anthropic"
)

var client ai.Client = anthropic.New(os.Getenv("ANTHROPIC_API_KEY"))
```

Ендпоінти, яких провайдери не поділяють (embeddings, генерація зображень, аудіо,
файли, батчі), свідомо відсутні в інтерфейсі. Кожен драйвер подає їх власними
нативними методами, тож спільна поверхня лишається малою й чесною.

## Інтерфейс Client

```go
type Client interface {
	Generate(ctx context.Context, req *Request) (*Response, error)
	Stream(ctx context.Context, req *Request) iter.Seq2[Chunk, error]
}
```

`Generate` повертає цілу `Response`; `Stream` віддає значення `Chunk` у міру
надходження через range-over-func ітератор (Go 1.23+).

## Побудова запиту

`Request` несе модель, необов'язковий system-промпт, розмову й звичні ручки
семплінгу:

```go
type Request struct {
	Model       string
	System      string // необов'язковий system-промпт
	Messages    []Message
	Tools       []Tool
	ToolChoice  ToolChoice
	MaxTokens   int
	Temperature *float64 // вказівник: «не задано» відрізняється від явного 0
	TopP        *float64
	Stop        []string
	Format      *Format // попросити JSON; див. «Структурований вивід»
}
```

Обов'язкові лише `Model` і `Messages`; `Request.Validate` це перевіряє й
повертає `ErrNoModel` чи `ErrNoMessages`. `Temperature` і `TopP` - вказівники,
щоб «не задано» відрізнялося від явного нуля.

`Message` - це роль плюс список частин вмісту `Part`:

```go
type Message struct {
	Role  Role
	Parts []Part
}
```

`Role` - одне з `RoleSystem`, `RoleUser`, `RoleAssistant`, `RoleTool`. Конкретні
частини - `Text`, `Image`, `ToolUse` і `ToolResult`. `Part` - закритий інтерфейс:
його не можна реалізувати поза цим пакетом, тож драйвери роблять вичерпний
switch по ньому.

`Message` і `Response` (де)маршаляться в JSON, де кожна частина позначена полем
`"type"` (`text`, `image`, `tool_use`, `tool_result`), тож `Request` чи
`Response` можна зберегти, покласти в чергу або кеш і декодувати назад у
конкретні типи частин. Невідомий `type` - це помилка, а не тихо відкинута
частина. `Image.Data` кодується в base64, а `ToolUse.Input` лишається сирим JSON.

Конструктори покривають поширений випадок однієї текстової частини:

```go
ai.UserText("Яка столиця Франції?")
ai.SystemText("Ти лаконічний асистент.")
ai.AssistantText("Париж.")
```

## Generate

```go
resp, err := client.Generate(ctx, &ai.Request{
	Model:    "the-model",
	Messages: []ai.Message{ai.UserText("Привітайся.")},
})
if err != nil {
	// обробити помилку
}
fmt.Println(resp.Text())
```

`Response` тримає вихідні блоки асистента плюс службові дані:

```go
type Response struct {
	Model      string
	Parts      []Part
	StopReason string
	Usage      Usage
	Raw        json.RawMessage // оригінальний JSON провайдера
}
```

Хелпери: `Text()` склеює текстові частини, `ToolCalls()` повертає всі виклики
інструментів, а `ToolCall(name)` - перший виклик іменованого інструмента. `Raw`
зберігає оригінальний JSON провайдера для полів, яких цей пакет не моделює.

## Stream

`Stream` повертає `iter.Seq2[Chunk, error]`; ітеруй по ньому:

```go
for chunk, err := range client.Stream(ctx, req) {
	if err != nil {
		// після першої помилки стрім зупиняється
		break
	}
	fmt.Print(chunk.Text)
	if chunk.Done {
		fmt.Printf("\nusage: %+v\n", chunk.Usage)
	}
}
```

```go
type Chunk struct {
	Text     string    // інкрементальна дельта тексту
	ToolCall *ToolUse  // задано, коли чанк несе завершений виклик інструмента
	Usage    *Usage    // задано на чанку Done
	Done     bool      // позначає фінальний чанк
	Raw      json.RawMessage
}
```

Драйвери задають `Usage` на чанку `Done`; його лічильники нульові, коли
провайдер не повідомив usage.

## Інструменти

Опиши викличну функцію через `Tool`, тоді прочитай виклики моделі:

```go
req := &ai.Request{
	Model:      "the-model",
	Messages:   []ai.Message{ai.UserText("Погода в Києві?")},
	Tools:      []ai.Tool{{Name: "get_weather", Description: "Поточна погода", Schema: schema}},
	ToolChoice: ai.ToolAuto,
}
resp, _ := client.Generate(ctx, req)
for _, call := range resp.ToolCalls() {
	// call.Name, call.Input (json.RawMessage), call.ID
}
```

`ToolChoice` - це `ToolAuto` (вирішує модель), `ToolNone` (заборонити виклики)
або `ToolRequired` (примусити хоча б один виклик). `Tool.Schema` - об'єкт JSON
Schema; драйвери передають його у формі, якої очікує провайдер. Щоб відповісти
на виклик, додай повідомлення `RoleTool` із `ToolResult`, чий `ID` збігається з
`ToolUse`.

## Структурований вивід

Задайте `Request.Format`, коли відповідь має бути JSON, а не прозою:

```go
resp, err := client.Generate(ctx, &ai.Request{
	Model:    "the-model",
	Messages: []ai.Message{ai.UserText("Склади SEO-поля для цієї статті.")},
	Format: &ai.Format{
		Type:   ai.FormatJSONSchema,
		Name:   "seo",
		Schema: json.RawMessage(`{"type":"object", ...}`),
	},
})
if err != nil {
	// обробка помилки
}

var seo SEO
if err := resp.JSON(&seo); err != nil {
	// модель відповіла не тим значенням, яке в неї просили
}
```

```go
type Format struct {
	Type   FormatType      // FormatText (дефолт), FormatJSON, FormatJSONSchema
	Name   string          // назва схеми - для провайдерів, які її вимагають
	Schema json.RawMessage // JSON Schema; обов'язкова для FormatJSONSchema
	Strict bool            // просити провайдера дотримати схему точно
}
```

`FormatJSON` просить будь-яке валідне JSON-значення; `FormatJSONSchema` - таке,
що відповідає `Schema`. `Request.Validate` відкидає схемний формат без схеми
(`ErrNoSchema`) або зі схемою, що не є валідним JSON (`ErrBadSchema`), ще до
того, як драйвер щось із неї збудує.

**Провайдери різні, і драйвер цього не приховує.** Де провайдер підтримує
структурований вивід нативно - драйвер бере нативну підтримку. Де ні - просить
формат у промпті, однаковим для всіх драйверів формулюванням
(`Format.Instruction`), щоб провайдер-незалежний код лишався переносним. Драйвер,
який не може ні того, ні того, повертає `ErrNoFormat`; жоден не викидає запит
мовчки. `Response.Format` каже, що саме сталося:

| `FormatMode` | Значення |
|---|---|
| `FormatNone` | нічого не просили |
| `FormatNative` | провайдер дотримав формат сам |
| `FormatEmulated` | драйвер попросив формат у промпті |

Емульований формат - це прохання, а не гарантія. Ця різниця варта не лише
прочитання, а й дії:

```go
resp, err := client.Generate(ctx, req)
if err != nil {
	return err
}

var seo SEO
if err := resp.JSON(&seo); err != nil {
	if resp.Format == ai.FormatEmulated {
		// Модель попросили, а не обмежили. Ретрай, простіша схема чи інший
		// провайдер - усе доречно; сам запит при цьому правильний.
	}
	return err
}
```

Код, який не може працювати без **дотриманої** форми, має це сказати: перевіряй
`resp.Format == ai.FormatNative` ще до того, як робити виклик, або валідуй
розібране значення після. `Response.JSON` доводить, що відповідь **парситься**,
а не що вона відповідає схемі; локально проти `Format.Schema` не валідує жоден
драйвер.

### Розбір відповіді

`Response.JSON(&v)` декодує текст відповіді. Він розгортає відповідь, повністю
загорнуту в markdown-огорожу (провайдер, якого просили лише промптом, схильний
її додавати), і далі декодує строго:

| Відповідь | Результат |
|---|---|
| `{"a":"x"}` | декодується |
| те саме значення, повністю загорнуте в огорожу | декодується |
| `Sure! {"a":"x"}` | помилка: проза навколо значення |
| `{"a":"x"} {"b":"y"}` | помилка: два значення |
| огорожа всередині прози | помилка: відповідь - це проза |

Він свідомо **не** шукає першу `{` і останню `}`. Витягування JSON із довільного
тексту - це саме той шлях, яким хибна відповідь читається як правильна.
Відповідь зовсім без тексту (лише виклики інструментів) дає `ErrNoText`.

## Здатності, які виконує провайдер

Дехто з провайдерів уміє виконувати роботу на своєму боці - насамперед пошук в
інтернеті. Про це просить `Request.Hosted`:

```go
resp, err := client.Generate(ctx, &ai.Request{
	Model:    "the-model",
	Messages: []ai.Message{ai.UserText("Що вийшло цього тижня?")},
	Hosted:   []ai.Hosted{{Kind: ai.HostedWebSearch}},
})
for _, c := range resp.Citations() {
	fmt.Println(c.Title, c.URL)
}
```

Це окреме поле від `Tools`, і саме в цьому весь дизайн. `Tool` - це обіцянка,
що *ви* відповісте на `ToolUse` через `ToolResult`. Здатність провайдера
ніколи не повертається до вас: він виконує її сам і вплітає результат у
відповідь. Якби обидва види лежали в одному зрізі, кожен уже написаний цикл
обробки інструментів мусив би навчитися розрізняти, на що відповідати, а на що
ні - код, який далі компілюється й починає поводитися інакше, найгірший вид
зміни. Цикл, який ніколи не чув про `Hosted`, працює точно як раніше.

### Звузити пошук

```go
ai.Hosted{
	Kind: ai.HostedWebSearch,
	Web: &ai.HostedWeb{
		MaxUses:      3,
		AllowDomains: []string{"example.org"},
		Region:       "UA",
	},
}
```

Кожне поле `HostedWeb` - це обмеження, а не побажання. Провайдери виражають
різне: один приймає ліміт викликів, інший лише список дозволених доменів,
третій нічого. Драйвер, який не може виразити задане вами поле, повертає
`ErrNoHosted`, а не виконує ширший пошук, ніж просили: відповідь, зібрана з
джерел, які ви виключили, гірша за відсутність відповіді.

### Джерела

Цитати чіпляються до `Text`, який вони підтверджують, бо саме те, яке речення
підпирає джерело, і є сенсом джерел:

```go
type Citation struct {
	URL       string
	Title     string
	CitedText string // слова самого джерела, якщо провайдер їх дає
	StartByte int    // проміжок Text, який підпирає це джерело, якщо відомий
	EndByte   int
}
```

Провайдери дають або одне, або друге, рідко обидва. Хтось повертає фрагмент
джерела, яким скористався, і жодної позиції у вашій відповіді; хтось - байтовий
діапазон у вашій відповіді й ніколи слів джерела. Обидва нулі означають «це
джерело підпирає всю частину». Драйвер, чий провайдер рахує не в байтах,
конвертує або лишає діапазон нульовим, тож діапазон ніколи не буває хибним -
хіба що відсутнім.

### Чи пошук справді був?

`Response.Hosted` каже, що сталося з кожною здатністю, про яку ви просили:

```go
for _, h := range resp.Hosted {
	switch h.Mode {
	case ai.HostedNative:  // виконано, h.Calls разів
	case ai.HostedSkipped: // запропоновано, і модель не скористалася
	}
}
```

`HostedSkipped` - стан, за яким варто стежити. Провайдер може прийняти
інструмент пошуку й відповісти з пам'яті моделі, і ззовні обидві відповіді
виглядають однаково - саме так впевнена вигадка стає схожою на дослідження.
Коли це неприйнятно, скажіть про це прямо:

```go
Hosted: []ai.Hosted{{Kind: ai.HostedWebSearch, Policy: ai.HostedRequired}}
```

і пошук, якого не було, стане `ErrHostedRequired` замість відповіді.

`HostedReport.Calls` - скільки разів провайдер це виконав. Така робота зазвичай
тарифікується окремо від токенів, тож це єдине місце, де видно її вартість;
`Usage` лишається суто токенним.

### Коли провайдер не вміє

`ErrNoHosted`, ще до відправлення запиту. На відміну від `Format`, який драйвер
може попросити в промпті, пошук не емулюється: у драйвера немає власного
пошукового рушія. Якщо вам краще отримати відповідь без пошуку - повторіть
запит без `Hosted`; це один видимий `if`, а не тиха різниця в тому, на чому
побудована відповідь.

### Структурований вивід разом із пошуком

Низка провайдерів не поєднує сувору схему й серверний інструмент в одному
виклику. Драйвер, який знає, що його провайдер так не вміє, повертає
`ErrFormatWithHosted` до відправлення - краще, ніж дати провайдеру відхилити
запит своїми словами або віддати JSON, який тихо не відповідає схемі.

Обхід - два виклики: перший із пошуком і вільним текстом, другий без `Hosted`,
який перекладає цей текст у схему. Це коштує вдвічі й передбачувано, що є
кращим компромісом, ніж коректний за формою результат, який не є тим, про що
просили.

### Стрімінг

`Chunk.Citations` несе джерела в міру надходження подій, а `Chunk.Hosted` - звіт
на фінальному чанку. Цитата приходить у тому чанку, в якому провайдер її
оголосив, а це не обов'язково той чанк, що несе підтверджуваний текст, тож
збирайте власний список, а не зіставляйте їх позиційно.

## Мультимодальний ввід

`Image` - частина вмісту-зображення; подай або інлайн-байти, або URL:

```go
ai.Message{Role: ai.RoleUser, Parts: []ai.Part{
	ai.Text{Text: "Що на цьому зображенні?"},
	ai.Image{MIME: "image/png", Data: pngBytes},
}}
```

Подай інлайн `Data` з його `MIME`-типом, або `URL`, коли провайдер уміє
тягнути віддалені зображення. Драйвери кодують `Data` у base64, як вимагає їхній
формат передачі.

## Помилки

Неуспішну HTTP-відповідь нормалізовано в `*APIError`:

```go
type APIError struct {
	Status  int             // HTTP-статус
	Type    string          // тип помилки провайдера, якщо є
	Code    string          // код помилки провайдера, якщо є
	Message string          // людиночитне повідомлення, якщо є
	Raw     json.RawMessage // оригінальне тіло помилки
}
```

Розбирай через `errors.As`:

```go
var apiErr *ai.APIError
if errors.As(err, &apiErr) && apiErr.Status == 429 {
	// перевищено ліміт запитів
}
```

Валідація запиту повертає сентинели `ErrNoModel` і `ErrNoMessages` (звіряй через
`errors.Is`), а для хибного `Hosted` - `ErrBadHosted`, `ErrBadHostedPolicy` чи
`ErrDupHosted`.

Здатності провайдера додають ще дві, і обидві - від драйверів, а не від
валідації: `ErrNoHosted`, коли провайдер не вміє того, про що просять (або не
вміє під заданими обмеженнями), і `ErrFormatWithHosted`, коли він не поєднує це
зі структурованим форматом. `ErrHostedRequired` каже, що запит було відправлено,
а модель не скористалася здатністю, яку `HostedRequired` зробив частиною
домовленості.

## Для авторів драйверів: Options і транспорт

`ai` несе плюмбінг, який перевикористовує кожен драйвер, тож драйвери лишаються
тонкими.

`Options` - спільна конфігурація, зібрана з API-ключа й функціональних опцій:

```go
o := ai.NewOptions(apiKey,
	ai.WithBaseURL("https://api.example.com"),
	ai.WithHTTPClient(httpClient),
	ai.WithTimeout(30*time.Second),
	ai.WithMaxRetries(3),
	ai.WithHeader("X-Custom", "value"),
)
```

`Options.Do` виконує HTTP-запит із ретраями та jitter-backoff, повертаючи
фінальну відповідь (зокрема останню невдалу, щоб драйвери могли прочитати тіло
помилки провайдера):

```go
resp, err := o.Do(ctx, http.MethodPost, url, body, headers)
```

`SSEEvents` читає потік Server-Sent Events як ітератор `data:`-навантажень:

```go
for data, err := range ai.SSEEvents(resp.Body) {
	// data - навантаження одної SSE-події
}
```

Ці три - `Options`, `Options.Do` і `SSEEvents` - усе, що потрібно драйверу, щоб
говорити HTTP і стрімінгом узгоджено з рештою набору.
